# BUG-0007：朝局决策上限与锦衣卫回奏口径

状态：实现中。来自[首次实玩](../archive/court-playtest-2026-09-23.md)，HANDOFF 切片 A。

## 决策上限吞掉被拿问者的最后决策

现象：`maxDecisions = 80` 在后期用完，郑泌昌被拿问后没有最后决策。

根因：`wake` 把所有唤醒一视同仁地计入上限，满额后静默不排决策，连被革职者那一次也拦掉了；拦掉时也不留记录，看起来像人物主动沉默。

方案：上限只作成本护栏，只计在任时的常规决策；被革职者的最后决策不受限。常规决策被护栏拦下时提交 `npc.wake_capped` 事件并计数，御前界面和复盘都显示，不伪装成人物不作为。数值：首局约 86 次调用；现行规则下四人每两日至多一次，一局理论上限约 150 次，护栏定为 160（约 250 万 token），B 切片加入吕芳后按实玩再调。

## 锦衣卫回奏的淹田与放赈

现象：回奏把买走的淹田算成“淹田 0 万亩”，把沈一石以粮换田的粮算成“官府放赈”。

根因：`floodedMu` 表示仍在百姓手里的淹田，买田会扣减它，回奏却拿它当受淹面积；`reliefDelivered` 把官仓、军粮、商人粮混在一起。

方案：县里新增 `inundatedMu`（汛时受淹面积，此后不变）和 `merchantGrainDelivered`（商人以粮换田的粮）；`reliefDelivered` 只计官仓与军粮。回奏、查勘所见和复盘表按新口径显示。

验证：单元测试覆盖护栏满额后被拿问者仍有最后决策、护栏计数，以及买淹田、以粮换田后回奏数字；实玩一局。
