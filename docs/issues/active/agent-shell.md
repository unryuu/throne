# FEAT-0009：人物 agent 化（假终端实验）

状态：实验完成，已接入引擎（2026-10-06），现行规则见 [ADR 0008](../../architecture/0008-terminal-actors.md)；精力已改为每日 1 点、上限 3 点。

构想：每个人物是带工具的 agent，按回合（每日）行动；引擎维护客观状态，人物经工具查询和提交意图。通信（写信、拜访、调查）经引擎递送，引擎不解读内容。同一天内大家看到的是当天开始时的世界，意图在日终统一结算。

## 实现

- 解释器 `packages/court/src/shell.ts`：把人物可见输入（`buildNpcInput`）摊成只读文件树（`profile.txt`、`log/` 每条经历一个文件、`province/`、`contacts.txt`、`abilities.txt` 等），支持 ls、cat、head、tail、grep、wc、sed -n、echo、cd、管道、`&&`/`||`、for 循环和变量；`send` 发文书、`act` 办事、`pending`/`cancel` 改主意，都只排进当天的意图。上限沿用现行规则：三份文书、三件事；另设每天 30 条命令。用 `end` 收笔并写下 inner。
- harness 插件 `packages/agent-runtime/court-shell/`：照 dsh-anchored-standard 的 `custom-bash` 注册同名 `bash`，只读快照 `world.json`，意图写回 `state.json`。harness 是子进程、不能回调引擎，但“看当天开始时的世界、日终统一结算”正好不需要回调。已核对 `request/header`：模型只看到这一个 bash 和我们的系统提示词。
- 没用 prefab：把 help 的输出直接放在首条消息里，效果相同，也不碰会话内部结构。
- 复跑：`npx tsx apps/web/server/agent-shell-day.ts [runId] [actorId] [第几次决策] [--no-oneshot] [--dry]`。脚本把存档回放到那次决策前，用现行输入跑假终端一天，并行跑一次现行填表做对照，结果写到 `runs/agent-shell/`。

## 结果

第三局郑泌昌第 12 次决策（四月三十，皇上准胡宗宪覆勘、吕芳诘问报数参差、桐庐堤停工），输入 2.3 万字。

|                  | 一次填表      | 终端 1（工具有缺陷） | 终端 2        | 终端 3        |
| ---------------- | ------------- | -------------------- | ------------- | ------------- |
| 命令 / 报错      | —             | 25 / 9               | 15 / 1        | 15 / 0        |
| 模型请求         | 1             | 15                   | 11            | 9             |
| 耗时             | 61s           | 56s                  | 83s           | 83s           |
| 未命中缓存的输入 | 14.3k         | 14.8k                | 22.7k         | 17.1k         |
| 缓存命中         | 0             | 155k                 | 164k          | 109k          |
| 输出（其中思考） | 11.7k (11.0k) | 8.6k (6.1k)          | 15.9k (14.2k) | 15.3k (13.5k) |

- 会先自己查：三次都先看身份、能力和新经历再动手；两次用 for 循环把全部经历读了一遍。第一次读完新信件后，又用 grep 搜旧事（台饷、盐课、决口）。
- 一天几步：9–15 次请求、15–25 条命令。命令上限 30 没碰到。
- 成本：未命中输入是填表的 1.0–1.6 倍，输出 0.7–1.4 倍，另有 11–16 万缓存命中；耗时 1–1.4 倍。各人物可以并行，一天的墙钟时间看最慢的那个人。
- 行为：一次填表和第三局原决定几乎一样。终端三次的决定各不相同：终端 1 不给吕芳回信，改给严嵩写密禀，并在 `pending` 后撤回奏疏重写；终端 2 办了三件事。内心更有“想一套说一套”的层次，例如“台饷我嘴上说挪盐课，其实盐课早空，只能拿这话拖一拖”。样本只有三次，只能说明方向。
- 工具教训：模型的第一反应就是 for 循环和批量 cat，不支持就白耗几步；办事命令原名 `do`，撞上 bash 关键字。现已改为 `act` 并支持循环。

## 留给引擎设计

- 收笔：起初约定“最后一段话就是内心”，三次都带了“收笔。”“我此刻的想法：”之类的前缀。已改为 `end --text` 命令（2026-10-06），复测干净；没收笔就在同一会话提醒一次，仍不收笔算调用失败。
- 模型倾向读完全部经历。后期经历变长时，步数和输入都会增加，但大部分落在缓存里。是否需要“只看新的”之类的入口，等长局实测再定。
- 拜访、暗中调查可以做成新的命令，结算留在引擎。拜访：同城、可被拒，别人可能知道“见过”但不知内容。写信、拜访、调查都经引擎递送，引擎不解读内容。
- 关系目前只是档案里的文字。等拜访、请托做出来，再让关系决定别人肯不肯替你办事。

## 接入后首次实玩（2026-10-06，15 天）

存档 `fe975e4d`，皇帝照票拟批、第 8 日派锦衣卫。24 次决策无一失败，共 202 次模型请求（每次决策平均 8.4 次），未命中输入 12.7 万、缓存命中 120 万、输出 16.4 万 token；推进一日 1–2 分钟。

- 精力没有起作用：人物至少隔一日决策，每次决策都是满的 4 点，没有一条“精力不济”。现行数值等于“每次最多四件事”，要改数值或节奏才有约束。
- 想一套说一套很充分，例如杨金水“桑田成了是我的功，办砸了先问外朝”，郑泌昌“对胡宗宪说照时价、不抑勒，实则契约仍操在我手里”。人人几乎每次都写满三份文书。
- 终端缺口：`2>&1`、往 `/tmp` 写草稿再发、`bash -c`、`$(...)`、`find`。已补：重定向、`/tmp` 可写草稿区、`<` 读入、命令替换、`bash -c`、`find`、`sort`。
