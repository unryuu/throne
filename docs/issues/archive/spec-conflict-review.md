## 详述

### C1 固定党派标签（冲突，优先修）

`bureaucracy-cycle.ts` 给每个 actor 存 `faction`，并据此分配任务。SPEC §11 明确禁止把"固定原型"当主要决策模型；ADR 0007 也要求**立场/派系归属必须派生**。
**建议**：删除 `faction` 字段，改由 `ideology` 的符号派生 `deriveFactionAlignment(actor)`；藩篱与"党争"从关系网与信念涌现，而非预贴标签。

### C2 存储型影响力（精神冲突）

actor 上的 `influence: number` 是一个可直接读写的权力标量。SPEC §7 要求实控由关系/资源/服从派生，不得设单一权力值。当前它既影响票数又当"庇护"，是"关系"与"权力"的混合。
**建议**：把 `influence` 视为"派生指标"（由职位、关系强度、资源控制算出），或下沉为 `ControlRelationship` 的聚合；世界模型保持关系化。

### C3 全局轮次（张力）

`court.round` 是每 20 刻一次的全局同步轮。SPEC §9.1 要求"不同系统不同分辨率、推进到下一个事件而非全局 tick"。当前虽非"每 actor 每刻遍历"，但仍是单一全局节拍。
**建议**：短期在文档中说明这是 MVP 简化；中期改为**多分辨率调度**（结算/审计/朝议各自周期）。

### C4 客观信息进入（潜在冲突）

`offenceContext` 让"行为体"读取客观 `ruleStreak`、`exposedIds`、上级真实影响力。用启发式时是引擎内部计算，尚可；但该路径设计为可替换 LLM 决策——直接喂给 LLM 就违反 §4（模型不得见客观真相）。
**建议**：接入 LLM 前，一律经 `official-belief.ts` 的**角色可见 context**（只给感知到的检测风险、自身动机、已知关系），绝不传客观账目与全局真相。

### C5 财政范围（范围张力）

征收、配额、中饱等抽象流量属 §21 允许的资源；但已接近 §26 排除的"现实经济"。当前只做抽象账户/流量，未做价格/市场/人口。
**建议**：以 ADR 0002（资源与财政层）为准绳；ADR 未获接受前，视这些模块为**实验性演示**，不入 MVP 规范。

## 处置计划（建议顺序）

1. **C1**（删除党派标签、改派生）——与 ADR 0007 一致，影响面小、收益大；
2. **C4**（LLM 前过滤角色可见）——接 API 前的硬前置；
3. **C2**（影响力派生）——需与 ADR 0007/0009 一起设计；
4. **C3**（多分辨率调度）——中期；
5. **C5**——等待 ADR 0002 评审结论。

以上 C1/C2/C4 属"扩大或触碰 SPEC 边界"，按项目规则应**先落 ADR/评审，再改实现**；本文件即为该评审的入口。
