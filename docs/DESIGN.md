# Throne 玩法设计补充

状态：第一版，2026-09-18。记录已确认的设计意图与待验证方案，不是新增功能排期。

## 1. 与 SPEC 的关系

[SPEC.md](./SPEC.md) 继续规定模拟规则、架构边界、MVP 范围和完成标准。本文说明这些机制应当形成怎样的体验，不重复 SPEC 中的信息隔离、事件调度、角色认知分层等规范。设计来源是项目初始讨论，以及本轮关于注意力、信任、角色处境和历史解释的策划讨论。

本文区分三种成熟度：**原则**是开发相关机制时就应遵守的方向；**后续目标**是已经认可、但尚未进入当前 MVP 排期的体验；**候选方案**是需要原型验证的实现思路。示例用于解释因果关系，不要求开发同名事件或固定结局。

新增设计不自动扩大当前 MVP，不要求中断正在进行的开发。若本文与 SPEC 存在实际冲突，开发窗口应指出具体冲突，由策划讨论形成决定后同步规范；不能默认较新的文档覆盖较旧的文档。

## 2. 玩家可以追求任何目标，但始终是处境中的人物

**原则。** 玩家可以追求延续国祚、百姓幸福、家族利益、享乐、个人荣耀或清除异己。游戏不预设所有人都要最大化国力，也不以“明君路线”作为唯一正确玩法。核心要求是：玩家所操作的人物拥有具体的信息渠道、关系、资源、身体和行动限制，其他人物具有各自的目标与自主性。

**后续目标。** 同一世界可以由人类游玩，也可以交给具有不同目标的 LLM 人物持续运行。二者遵守相同的世界规则与角色信息边界。游戏侧重有意义的选择和易于操作的呈现，批量模拟侧重记录、比较与分析；不为了制造戏剧效果而给予玩家特殊的因果待遇。模拟结果能否解释现实社会，需要另行验证，不能仅因产生大量数据就视为有效的社会科学结论。

是否需要结局评价，以及如何呈现多种个人成就，尚未确定；不妨碍先建立自由目标下的行动与后果。

## 3. 注意力、亲力亲为与授权

**原则。** 对同一问题投入合理的调查与核验，应当通常获得更可靠的证据，并提高相关人员欺骗成功的难度。收益来自实际接触的信息、独立渠道和交叉核实，不能把“亲自调查”做成读取后台真相的按钮。亲眼所见仍受行程安排、接触对象、专业知识和对方布置的影响。

**后续目标。** 时间与精力限制介入的广度和深度。亲自核查一件事会占用处理其他事情的机会；更多核查也可能逐渐只增加少量信息。人物在调查、出行、等待与会谈时，世界继续运行。玩家在屏幕前思考多久，不等于角色可以在游戏里免费完成无限次调查。

授权应当成为有价值的选择。玩家通过用人、职责划分、独立报告渠道、抽查与申诉程序，让大多数事务无需自己逐项介入。频繁越级接管可能使下属等待批示，造成新的积压；可靠的授权则可能扩大处理能力，但也增加对具体人物的依赖。效果来自组织行为，不应给所有授权统一附加惩罚。

## 4. 公平、履历与追随关系

**原则。** 发现问题、作出公平处置、带领他人办成事情，是不同的经历，不能统一换算成全体人物忠诚上涨。

发现问题可能让人认为执政者难以欺骗；保护报信者、区分无力完成与蓄意欺瞒、避免让无辜者顶罪，可能让人相信说真话和认真办事值得。人物依据自己获知的过程、所受影响及其公平观形成判断。获益者、受罚者和旁观者可以产生不同反应，未获知事件的人不能立即同步更新态度。

**后续目标。** 信任的变化体现为报信、合作、承担风险和危机中的支持。公平处置可以改善后续信息质量，惩罚坏消息的传递者则可能推动隐瞒。私人感激、对判断能力的信任、对程序的认可和利益依附可以同时存在，不必同步变化。

人物还应记得“跟谁做事能成”：承诺是否兑现，谁付出成本，谁获得收益，失败时是否被抛弃。成功的历史可以增加未来的合作意愿，但不同人物对“成功”的定义不同，功劳归属也取决于其认识。皇帝拨款、宰相组织、将军发饷，士兵可能把主要功劳归给将军。

能臣完成任务的同时，可能积累自己的关系和动员能力。国家能力增长与君主个人控制力增长并非总是一回事，也不要求能臣事先怀有谋反意图。

## 5. 身体与情绪是实际约束

**后续目标。** 疲劳、休息和情绪应实际影响角色的行动与信息处理，而非只写在人物描述里。角色状态可以影响持续专注的能力、注意哪些线索、如何理解中性表达，以及采取某种行动的冲动。不能只靠操作者愿意扮演这些限制。

**候选方案。** 在外部信息到达之后，增加独立的情绪处理层，可由 LLM 辅助表现人物的注意与解释。沿用 SPEC 的信息链条，区分到达的信息、人物当时注意到的内容，以及形成的理解。例如“尚需商议”的回信可以被人物视为谨慎，也可以被理解成挑战权威。

情绪处理不能任意改写信件原文或已发生的外部事实，也不能读取角色未知的秘密。实际收到的信息及其解释应可追溯；花时间重读、咨询或休息，可以成为重新评估的途径，但不保证必然获得正确答案。LLM 生成的表达不能绕过已有的世界提交与记录机制。

独立 LLM 是否必要、哪些约束由规则负责、影响强度如何设定，尚待验证。这里是模拟假设，不是临床诊断系统。也不能假设一段“你很愤怒”的提示就能可靠地约束 LLM，或强迫人类操作者产生相同情绪。

## 6. 享乐与省心必须具有吸引力

**原则。** 角色快乐与操作者获得回报是两回事。仅提供“快乐增加、国库减少”的选项，无法让以国力为唯一目标的操作者感到诱惑；把享乐仅做成精力补给，也不能完整表达私人欲望。休息和娱乐本身不等于昏庸。

**后续目标。** 享乐、亲密关系、荣耀、支配、被肯定和逃避烦扰，应当拥有可追求的内容。对于人类，可以通过关系、叙事和实际操作体验形成吸引力；对于 LLM，私人目标需要在角色任务与评价中有真实位置，不能一面要求最大化国力，一面期待它因奉承而偏离唯一目标。

一个值得验证的方向是“省心带来依赖”：某位大臣确实办成过事，也能替统治者实现个人愿望，因此逐渐得到筛选信息、安排人事和组织执行的权力。便利是真实的，形成的依赖也是真实的。此人不必是预设奸臣，这段关系也不必必然走向灾难。具体的私人生活内容与回报形式尚未定案。

## 7. 多重动机、后果与历史解释

**原则。** 同一行动可以同时满足多个目的、损害另一些目标。动机可以冲突，也可以在过程中变化。人物依据当时有限的信息、预期和时间压力行动，不拥有后见之明；不能用一个“真实动机”标签替代其处境。

例如开凿运河可能改善运输、消耗劳役、改变地方收入、培养支持者，也可能满足个人功业欲。由谁主持、向谁筹资、先修哪段、给谁补偿，会改变这些后果。应让解释依托实际的资源与关系变化，而非只为单一数值效果生成褒贬文案。

事实分歧与价值分歧需要区分。是否挪用了粮食可以调查；同一工程既劳民伤财又巩固统治，则可能是同时成立的评价。系统不必裁定唯一正确的道德结论。

人物对事件的理解也参与因果过程：认为自己将被排挤的人可能抵抗，相信长期收益的人可能承担眼前成本。公开说辞能否说服别人，取决于利益、既有信任与实际行动，不能因措辞漂亮就自动增加支持。回放应帮助理解当时的处境，不把最后的成败当作当初动机或判断质量的唯一证明。

## 8. 奏疏、随机事件与逐步展开的细节

**原则。** “重大”取决于观察者和承担后果的人。朝廷眼中的普通修桥申请，可能决定当地商人的生计、某个家族的收入和县令的仕途。不能把复杂动机只分配给预设大事件。

**后续目标。** 允许先以奏疏或事件的简要形式引入事情，再随调查、利益冲突、人物互动和局势变化，补充需要的细节。不是所有人和事件都需要一开始完整展开；也不是每封奏疏都必须藏有阴谋。随机事件可以提供与世界条件相容的新情况和压力，政治上的服从、抵抗或失控仍由现有因果机制产生。

逐步展开须保留三种区别：世界中已经成立但角色未知的事实、尚未具体化的细节，以及此后新发生的事情。第一种通过信息渠道揭示；第二种可由生成机制提出、在世界约束内确认并记录；第三种经过正常行动和事件过程发生。LLM 可以提出细节，不能自行宣布世界真相。

已有事实、资源约束、身份连续性和已发生的结果必须保持一致。会决定当前争议结果的重要事实，应在其参与判定前确立并记录，不能看见玩家的选择以后，再补造一个决定性的旧关系来推翻其判断。尚未展开的角色也不能在升格时获得与既有经历矛盾的过去。已确认的生成结果纳入记录，回放不重新生成。

哪些细节预先确立、哪些延后生成，以及如何约束生成内容，是待验证方案。目标是在保持因果可信的前提下，把表现与计算投入到正在变得重要的地方，而非先写出所有人的完整人生。

## 9. 少重复操作，保留真实的处理过程

**原则。** 人物承担的工作量与操作者的重复劳动应分开。调查十座粮仓可以消耗数天、人员和资源，但不要求玩家重复十次相同操作。玩家主要选择调查什么、委托谁、如何验证，以及怎样处理发现的问题。

呈现和操作可以概括，实际执行仍受能力、时间、信息和他人意愿约束。普通事务可以按已授权的流程运行；争议、失败、申诉或抽查可以带来进一步介入的机会。这些渠道也可能受阻，不能保证所有严重问题自动送到玩家眼前。

什么能够上达统治者本身就是政治机制。玩家建立的是允许大多数事情在下面解决、同时仍有机会发现异常的体系，不应被迫逐封奏疏排雷。事件的重要程度、模拟展开程度和界面展示篇幅，不必相同。

## 10. 开发协作与方向复核

开发窗口继续自主安排实现顺序、拆分任务和维护 [STATUS.md](./STATUS.md)。策划侧在形成新意图或完成若干有意义的演示后复核方向，不逐步审批日常开发。需要改变 SPEC 核心原则、技术限制明显改变体验、或必须作出尚未确定的玩法取舍时，再带回讨论。

本文首次应在当前开发切片收尾、规划下一切片之前阅读。当前进度以 STATUS 为准；本文不另存一份开发快照，也不要求把上述后续目标全部插入现有计划。以后规划相关机制时重读对应部分即可。

复核时关注实际过程：角色的信息从哪里来；行为是否有其处境中的理由；结果是否经过真实执行；省略操作是否偷换成保证成功；新增细节是否尊重已有历史。发现偏差时指出具体行为及对应原则，同时区分暂时的 MVP 简化与需要纠正的设计方向。

## 11. 方向：长期统治与“嘉靖 / 崇祯模拟器”

**原则。** 2026-09-23 确认：项目研究的是一段长期统治，而非单场危机。参照物是嘉靖、崇祯这类统治者：前者深居西苑、靠票拟批红与人事制衡掌控朝局；后者事必躬亲、屡杀重臣，逐渐无人敢言。二者对应第 3、4、6 节的授权、惩罚与依赖问题。主玩法是奏疏流转：谁上奏、谁票拟、谁批红、谁留中、谁拖延、谁压下不报。

乐子优先，由乐子反馈驱动迭代。先做可玩的实名版本：统治者由玩家扮演，人物使用历史或《大明王朝1566》中的名字。严肃模式（全员交给 LLM、设定不同边界条件）与化名对照（排除模型背诵历史，检验局面是否由机制推出）是后续目标。

人物可以想一套、说一套、做一套。私下想法、写给别人的文书、实际行动分别记录；统治者只能看到送到面前的文书。引擎保持通用，明朝中后期作为场景包放在引擎之上，这修订了 SPEC §26“不做真实历史国家”的 MVP 限制。
