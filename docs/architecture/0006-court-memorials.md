# ADR 0006：奏疏流转与“想 / 说 / 做”

状态：采纳，2026-09-23。方向见 [DESIGN §11](../DESIGN.md#11-方向长期统治与嘉靖--崇祯模拟器)。

新增 `packages/court`，首个场景为嘉靖朝“改稻为桑”。现在场景内容和朝廷流程放在同一包内，等第二个场景出现后再抽出通用引擎。

**时间。** SimTime 以时辰为单位，一日十二时辰。日期按每月三十日近似显示，不做真实农历。北京与杭州之间单程六日，密奏五日；北京的御览在午时，NPC 最早在次日辰时处理新收到的内容。

**御览。** 有文书送到御前时，于下一个午时开御览，世界暂停，直到玩家“御览毕”。外朝奏疏先送内阁，由严嵩在御览前票拟；织造局密奏和锦衣卫回报经司礼监直达。玩家对每份文书可以依拟、改批或留中，也可以发特旨。批红动作只能从引擎定义的敕令中选择，朱批文字随敕令送达，由收件人自己理解。留中不发送任何内容；奏疏发出二十日仍无批复，上奏人只会得知“未见批复”。若十日内没有文书上达，也照常开一次御览，御案可以为空。

**想 / 说 / 做。** 每次 LLM 决策输出三部分：内心（第一人称，局终才公开）、文书（奏疏、密奏、私信，经信道送达，收件人才看得到）、行动（能力 id 加参数）。内心是角色的剧中产出，不是模型推理；原始 reasoning 仍不落盘。严嵩还要为每份待票拟奏疏给出建议敕令和票拟文字。

**行动校验。** 输出格式错误时，同一人物以同一输入自动重问一次；仍然错误，才视为调用失败，由玩家显式重试。服务商错误不自动重试。能力 id 未知时记为 PrimitiveGap，不算失败。已知能力若缺少实际条件（不在辖区、已被革职、时机已过），作为失败的尝试记入历史并告知本人。命令本身不产生效果：赈灾、查勘等敕令只会进入 NPC 的输入，由 NPC 决定是否执行、如何执行。

**世界规则。** 汛期强度、查勘时能否发现证据，由局号和固定键的哈希确定，结果写入已提交事件，因此重放不需要重新随机。毁堤、买田、赈灾、民变、死亡等后果由引擎计算，模型只能提出意图。汛前完工的修堤会补好此前的掘堤，但掘堤留下的证据不会消失。

**信息边界。** NPC 输入只包含本人档案、本人收到的文书、本人的观察（辖区实情、查勘所得、自己行动的结果）和本人的历史决策。统治者视图只含送到御前的文书、票拟和自己的批红与特旨。局终复盘并列显示所想、所言、所为和实情。

**频率与失败。** 同一人物两次决策至少相隔两日，其间收到的内容合并处理。同一时刻的多个决策并行调用；已成功的调用在本局内缓存，重试只补做失败的调用。每次推进结束后存档；服务重启时按已提交事件与未消费队列恢复，不重新调用模型。常规决策设成本护栏（每局 160 次），满额后的唤醒提交 `npc.wake_capped` 并在御前和复盘中显示；被革职者的最后一次决策不受护栏限制。

**本切片不做。** 严嵩不能被革职（首辅的继任票拟另做）；吕芳只转呈，不过滤；海瑞、严世蕃、沈一石不是 LLM 人物，沈一石作为按规则买田、借粮的商人。
