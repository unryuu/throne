# ADR 0012：开局包、调用指纹库与杂事奏疏库

状态：草案，2026-10-15；承接 ADR 0010、0011。只对新局生效。

## 用意

网页版玩家多半只玩一两天，所以先让开局几天不用等、少花钱。思路是让大模型和古典文字游戏互补：大模型写过的东西存下来反复用，成了一棵边玩边长的决策树；不需要大模型的装饰性内容，改用手写的库。后期的等待另议（让北京三人的东西在朝会中途送到）。

## 调用指纹库

- 每次模型调用（含人物终端日、吕芳当面回话、通政司、归纳、深思）先算指纹：发给模型的完整请求（模型名、参数、系统提示词、输入），去掉局号。终端日以当天开场请求为准，缓存整天的结果（最终决定加终端记录）。
- 库里有同指纹就直接用，调用记录标 `cached`，用量记 0；没有就现场调用，校验成功后结果也写进库。玩的人越多，命中越多。`runs/cache/calls/` 按指纹独占锁、原子写入；损坏文件和超时遗留锁显式报错，不吞错回退。终端结果包含完整命令记录，指纹包含可读输入、工具实现与运行参数。
- 提示词、规则、杂事库一改，指纹自然对不上，退回现场调用，不会拿过期的结果冒充。
- 要求一字不差。按 2026-10-15 实现 brief，新局文书改按发件人／来源各自计数，局号不再进入新局人物提示词。开局事件记编号版本与种子；旧档没有版本字段，仍按全局流水号重放。不得删掉模型真正看到的分支差异来制造命中。

## 开局包

- 一组开局包 = 固定的随机种子 + 开局设置（文言档、归纳开关）+ 预跑进指纹库的调用。种子从局号拆出来单独存：新局有自己的局号，种子取开局包的。
- 每组预跑第 0 天两份奏疏的 3 × 3 条分支（改稻为桑、胡宗宪请饷，各取依拟 / 留中 / 驳回；驳回用标准措辞），每条之后一路默认推进到第 5 天。浙江三人头 5 天各分支输入相同，自然共用。
- 默认分支上，第 0–2 天每天只预跑召吕芳的三句预设，以及向北京的严嵩、吕芳、陆炳各问三句预设；每条只推进到下一天朝会。第 0 天每条消息的深思照旧预跑。浙江人物的问题和其余特旨（赈济、查勘、申饬、拿问、准行改桑）不预跑，玩家选后由正常缓存／现场调用处理。
- 数量：浅白 6 组，文言、现代各 2 组。网页版默认浅白。
- 新开一局按文言档随机抽一组，浏览器记住抽过的，下次避开。
- `pnpm opening-packs --register=all` 重跑浅白 6、文言 2、现代 2 组；可用 `--groups=N --parallel=N --summaries=true|false` 调整。常规包号和种子固定，重跑补全同一组；只在全部任务成功后发布清单。完整结果与用量在 `runs/cache/reports/`。
- 小规模冒烟：`pnpm opening-packs --register=plain --groups=1 --default-only --days=2 --parallel=1 --verify`，使用独立包号；不进入随机抽包池。`--verify` 禁止任何缓存未命中的现场调用。
- 预设从默认路线第 0–2 天的朝会记录独立分叉，每天 3 条召见 + 9 条北京发问，分别停在第 1、2、3 天朝会，不继续跑到第 5 天。第 0 天每条深思先独立展开该消息。任意连续组合／任意阅读顺序不属于有限预跑覆盖。
- `pnpm opening-packs --register=all --plan` 只打印每组任务清单、条数及调用／费用粗估，不调用模型、不写缓存或发布包；即使同时传 `--verify` 也只规划。规划和执行共用任务定义。第 0 天消息数由种子和现有开局规则计算，执行时核对实际案头；估价沿用已记录冒烟的平均调用量和当时峰／谷费率，不扣除指纹命中、不是报价或费用上限。

## 预设选项

发问、特旨、召吕芳的菜单先列三四条写好的，最后一项才是自己打字。预设的措辞固定，所以能命中。自己打的照常现场调用。

## 杂事奏疏库

- 通政司的“朝政杂事”不再让模型自拟，改从库里按种子抽，同一局不重样；只抽不限时令或当前月的条目，整条随 fact 入档，回放取快照。
- 每条：标题（≤20 字）、正文（≤120 字）、一句归纳、适用月份、出处说明。取材《世宗实录》等史料里的真事，可化用，要好玩。每条备两份措辞：公文体（文言、浅白两档共用）和现代汉语（现代档用）。
- 抽出的条目不进通政司那次调用，也不进归纳调用（自带归纳）。当天全是杂事时，通政司不调用模型。
- 库放在 `packages/court/data/routine/`，由网页版 Claude 按 [提示词](../prompts/杂事奏疏库-提示词.md) 写成 markdown，用户审；引擎解析时检查字段和字数。库抽完了就退回模型自拟。
- 只加载顶层 `*.md`，`drafts/` 留作未完稿；文件名 `来源 - 批次.md` 的来源与编号组成唯一键（无 `-` 时用整个文件名作来源）。每次增补后运行 `npx tsx apps/web/server/routine-library.ts` 自检各来源、类别、可信度计数及全部校验警告。

## 深思附作者注

深思独白后，必要时附不超过两行“游戏作者注”：跳出嘉靖视角，讲一条相关的明代制度或史实，寓教于乐。没有值得讲的就不写。作者注单独显示，和独白分开。杂事库有作者注时优先用已存 fact 的作者注，空白才用模型所写；深思独白仍调用模型。

## 留中的说法

引擎里留中是终局：不批、不发，之后不能再批这份（可另发特旨），作者 20 天后发觉没回音。菜单措辞跟着改：有票拟的写“留中 — 不批不发，搁着不表态”；没有票拟的消息不显示留中，退朝时记为“已阅”。

## 等待提示

没命中时等待照旧，但要显示进度，比如“严嵩正在拟票……”“吕芳在司礼监理事……”，只说谁在忙，不透露在做什么。

## 验收

- 一路依拟的新局：开局和前 5 天的退朝等待接近 0。
- 9 条分支各抽一条实测命中；偏离分支后浙江三人在第 6 天前仍命中。
- 实测命中率与每组开局包成本记入 FEAT 文档。
